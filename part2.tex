
\section{Архитектура и проектирование модулей системы}

\subsection{Общая архитектура системы и сценарий работы}
\label{sec:architecture}

Разрабатываемая интеллектуальная обучающая система (ИОС) реализована как 
веб-приложение на базе фреймворка Django~\cite{django2026docs} с использованием 
архитектурного паттерна Model-View-Template (MVT). Архитектура системы 
подразделяется на шесть функциональных модулей: управление пользователями 
и ролевой доступ, конструктор учебного контента, модуль психодиагностики 
и когнитивного профилирования, адаптивная система тестирования на базе IRT, 
модуль контекстной адаптации и подсистема аналитики с рекомендательным 
движком. Взаимодействие между модулями построено по принципу слабой 
связанности (Loose Coupling) с активным использованием сигнального 
механизма Django и RESTful API-эндпоинтов, что обеспечивает независимое 
масштабирование компонентов и упрощает их тестирование~\cite{gamma1994design}.

Полный сценарий взаимодействия системы с пользователем охватывает 
непрерывный цикл обучения и включает следующие этапы:

\begin{enumerate}
    \item \textbf{Регистрация и инициализация.} Студент проходит регистрацию 
    через форму \texttt{UserRegisterForm}. Система создаёт учётную запись 
    (со статусом неактивной до подтверждения администратором), 
    инициализирует нулевой счётчик баллов активности (\texttt{activity\_score}) 
    и запускает фоновый сбор поведенческих данных. При первом входе 
    выполняется запрос к внешнему API для определения геолокации 
    по IP-адресу~\cite{ipapi2026} и инициализируется сессия трекинга 
    активности мыши.
    
    \item \textbf{Психологическое тестирование и профилирование.} 
    Студент проходит серию психометрических тестов. Система обрабатывает 
    сырые баллы, рассчитывает ключевые факторы A1–A4 и формирует 
    многомерный когнитивный профиль (\texttt{PsychProfile}), содержащий 
    персонализированные рекомендации в формате T/R/C (для преподавателя, 
    обратная связь, для комьюнити)~\cite{brusilovsky2007usermodels, conati2002bayesian}.
    
    \item \textbf{Первичная адаптация и выдача рекомендаций.} 
    Рекомендательный движок синтезирует данные когнитивного профиля, 
    поведенческие метрики (рассчитанные на основе трекинга мыши) и 
    текущее значение параметра контекстной активности~$P$. На основе 
    этих данных формируется индивидуальная траектория и ранжированный 
    список курсов~\cite{brusilovsky2007usermodels, ifenthaler2020learning}.
    
    \item \textbf{Обучение с контрольными точками.} Студент осваивает 
    материал через интерфейс \texttt{TopicDetailView}, где подача контента 
    может адаптироваться под предпочтительный формат. В контрольных 
    точках система инициирует адаптивное тестирование 
    (\texttt{AdaptiveTestView}), обновляет оценку способности~$\theta$ 
    по модели Раша, фиксирует прогресс (\texttt{TopicProgress}) и 
    пересчитывает контекстный параметр~$P$~\cite{vanlehn2006behavior, woolf2009building}.
    
    \item \textbf{Модификация стратегии и геймификация.} На основе 
    обновлённых данных система корректирует сложность последующих 
    заданий. Модуль геймификации начисляет баллы за активность и 
    успешное прохождение тем, причём визуализация прогресса и 
    соревновательные элементы динамически скрываются или усиливаются 
    в зависимости от уровня нейротизма (A3) студента~\cite{dominguez2013gamifying, plass2015foundations}.
    
    \item \textbf{Аналитика и наставнические рекомендации.} 
    Преподаватель через панель \texttt{InstructorDashboardView} получает 
    доступ к агрегированной аналитике, графикам психологического профиля 
    и метрикам вовлечённости. Система прогнозирует успеваемость 
    и формирует рекомендации по построению дальнейшей образовательной 
    траектории~\cite{ifenthaler2020learning}.
\end{enumerate}

\subsection{Модуль построения профиля обучающегося}
\label{sec:profile_module}

Модуль построения портрета обучающегося является ядром подсистемы 
персонализации~\cite{brusilovsky2007usermodels}. Он отвечает за агрегацию 
данных психометрического тестирования и поведенческой аналитики, 
формирование многомерного когнитивного профиля и генерацию педагогических 
рекомендаций. Алгоритмическая логика модуля реализована в функции 
\texttt{generate\_psych\_profile}.

Компонент психологического тестирования обрабатывает результаты, 
охватывающие четыре ключевых фактора когнитивного профиля, 
соответствующие методике ВКР:
\begin{itemize}
    \item \textbf{A1 (Мотивация по шкале МУН)} --- уровень учебной 
    мотивации, шкала от 0 до 20 баллов. Определяет направленность 
    обучающегося на успех или избегание неудач;
    \item \textbf{A2 (Экстраверсия по тесту EPI)} --- уровень 
    экстраверсии/интроверсии, шкала от 0 до 24 баллов. Характеризует 
    предпочтительный тип взаимодействия с учебной средой;
    \item \textbf{A3 (Нейротизм по тесту EPI)} --- уровень 
    эмоциональной устойчивости, шкала от 0 до 24 баллов. Критически 
    важен для дозирования стрессовых нагрузок и настройки 
    геймификации;
    \item \textbf{A4 (Темперамент по кругу EPI)} --- тип высшей 
    нервной деятельности (1---флегматик, 2---сангвиник, 3---меланхолик, 
    4---холерик).
\end{itemize}

Алгоритм обработки результатов включает строгую валидацию и нормализацию. 
Сырые баллы из модели \texttt{PsychTestResult} группируются по базовым 
факторам (с отбрасыванием суффиксов T/R/C), после чего для каждого 
фактора выбирается наиболее свежий результат. Значения жёстко 
ограничиваются диапазонами шкал (например, для A1 применяется операция 
$\max(0, \min(20, \text{val}))$). 

На основе нормализованных значений алгоритм обращается к таблице 
интерпретаций и генерирует рекомендации в формате JSON для трёх 
категорий: \textbf{T} (Teacher --- тактические рекомендации для 
преподавателя), \textbf{R} (Reflection --- обратная связь для 
самоанализа студента) и \textbf{C} (Community --- рекомендации по 
интеграции в учебное комьюнити). Эти данные сохраняются в полях 
\texttt{guidance\_A1} -- \texttt{guidance\_A4} модели \texttt{PsychProfile}.

\textbf{Обогащение поведенческими метриками.} 
Помимо психометрики, профиль обогащается данными неявного сбора. 
API-эндпоинт \texttt{mouse\_tracking\_api} принимает массив координат 
курсора и временных меток. Специализированный алгоритм 
(\texttt{calc\_motion\_metrics}) анализирует скорость движения, 
резкость изменений траектории и паузы, вычисляя поведенческие оценки 
мотивации и невротизма. Эти значения сохраняются в поля 
\texttt{mouse\_motivation\_score} и \texttt{mouse\_neuroticism\_score}, 
формируя истинно многомерную модель обучающегося, опирающуюся как на 
самоотчёт (тесты), так и на объективное поведение~\cite{conati2002bayesian}.

\subsection{Модуль контекстной адаптации и оценка внешних факторов}
\label{sec:contextual_adaptation}

Контекстная адаптация представляет собой корректировку поведения 
интеллектуальной обучающей системы (ИОС) на основе информации о внешних 
условиях функционирования, не зависящих непосредственно от учебного 
контента. В разрабатываемой системе реализован модуль контекстной 
адаптации, оценивающий три ключевых параметра: географическое положение, 
погодные условия и температуру воздуха~\cite{chen2008context, ipapi2026, openweathermap2026}.

Научное обоснование связи погодных условий с когнитивной продуктивностью 
восходит к исследованиям в области экологической психологии. Эмпирические 
данные свидетельствуют, что при температуре ниже 13~°C или выше 33~°C 
наблюдается статистически значимое снижение точности выполнения 
когнитивных задач и скорости обработки информации~\cite{keller2005warm}. 
Кроме того, пасмурная и дождливая погода снижает уровень серотонина, 
что отрицательно сказывается на концентрации внимания и рабочей памяти 
--- механизм, хорошо изученный в контексте сезонных аффективных 
расстройств~\cite{keller2005warm}.

Для количественной оценки влияния внешних факторов в системе введён 
интегральный параметр активности пользователя~$P$, рассчитываемый 
по формуле:
\begin{equation}
    \label{eq:P}
    P = K_{\text{region}} \cdot K_{\text{temp}} \cdot K_{\text{weather}}
\end{equation}
где $K_{\text{region}}$ --- региональный коэффициент, учитывающий 
климатические особенности; $K_{\text{weather}}$ --- погодный коэффициент, 
нормализованный к шкале 0--1; $K_{\text{temp}}$ --- температурный 
коэффициент, отражающий отклонение от комфортного диапазона.

Значение $K_{\text{temp}}$ вычисляется на основе текущего отклонения 
температуры с учётом нижней границы устойчивости системы:
\begin{equation}
    \label{eq:Ktemp}
    K_{\text{temp}} = \max\left(0{,}1; \ 1 - \frac{|T_{\text{current}} - T_{\text{comfort}}|}{T_{\text{max.diff}}}\right)
\end{equation}
где:
\begin{itemize}
    \item $T_{\text{comfort}}$ --- комфортная температура (в системе 
    принята за 20~°C);
    \item $T_{\text{current}}$ --- текущая температура воздуха;
    \item $T_{\text{max.diff}}$ --- максимальное допустимое отклонение 
    температуры (13~°C), при котором коэффициент снижается до 
    минимального порогового значения.
\end{itemize}

Выбор диапазона 15--25~°C как комфортного опирается на исследования 
терморегуляции и умственной работоспособности, а значение 
$T_{\text{comfort}} = 20$~°C соответствует середине этого диапазона 
и является стандартным нормативом для учебных помещений согласно 
ГОСТ~30494-2011. Нижняя граница $K_{\text{temp}} = 0{,}1$ введена 
намеренно: полное обнуление параметра~$P$ привело бы к отказу 
рекомендательной системы, что нецелесообразно, поскольку даже 
в экстремальных условиях ИОС должна функционировать в минимальном 
режиме~\cite{chen2008context}.

Значения коэффициентов определены на основе анализа психофизиологических 
исследований. Региональные коэффициенты (таблица~\ref{tab:region}) 
учитывают адаптацию населения к специфическим климатическим зонам.

Процесс обработки данных включает следующие последовательные этапы:
\begin{enumerate}
    \item \textbf{Идентификация местоположения.} IP-адрес пользователя 
    извлекается из HTTP-запроса (с учётом заголовков прокси-серверов) 
    и передаётся в RESTful API сервиса \texttt{ip-api.com}~\cite{ipapi2026}. 
    Сервис возвращает JSON-объект, содержащий информацию о стране, 
    регионе, городе и географических координатах.
    \item \textbf{Получение метеорологических данных.} На основе 
    полученных координат формируется GET-запрос к API 
    \texttt{OpenWeatherMap}~\cite{openweathermap2026}, предоставляющему 
    актуальные данные о температуре, атмосферном давлении, влажности, 
    а также код текущего погодного условия.
    \item \textbf{Обработка ошибок и фолбэк-механизмы.} Модуль 
    реализует трёхуровневую систему отказоустойчивости: (а) повторные 
    запросы при временной недоступности API (retry logic с 
    экспоненциальной задержкой); (б) использование кэшированных значений 
    при превышении таймаута; (в) применение дефолтных региональных 
    коэффициентов при полной недоступности внешних сервисов.
    \item \textbf{Расчёт интегрального показателя.} На основе 
    нормализованных значений $K_{\text{region}}$, $K_{\text{temp}}$ 
    и $K_{\text{weather}}$ вычисляется параметр~$P$ по 
    формуле~\eqref{eq:P}, отражающий текущую предрасположенность 
    обучающегося к эффективной учебной деятельности.
    \item \textbf{Интеграция с рекомендательным движком.} Рассчитанное 
    значение~$P$ передаётся в функцию \texttt{recommend\_courses\_for\_student}, 
    где используется как весовой коэффициент. При низком значении~$P$ 
    (неблагоприятные внешние условия) алгоритм может смещать приоритеты 
    в сторону курсов с меньшей когнитивной нагрузкой или корректировать 
    ожидаемое время выполнения заданий, обеспечивая педагогически 
    обоснованную адаптацию~\cite{brusilovsky2007usermodels}.
\end{enumerate}
\subsection{Модуль предоставления знаний и автоматический конструктор курсов}
\label{sec:knowledge_module}

Модуль предоставления знаний отвечает за формирование, структурирование и адаптацию образовательного контента. В разрабатываемой системе он реализован через набор представлений Django и включает три ключевых компонента, тесно интегрированных с базой данных.

\textbf{Компонент ввода и обработки материалов курса} автоматизирует подготовку мультимедийного контента. При загрузке аудио- или видеофайла через интерфейс преподавателя (\texttt{TopicContentCreateView}) срабатывает конвейер обработки (\texttt{process\_content}): извлечение аудиодорожки с помощью \texttt{ffmpeg}, транскрипция речи нейросетевой моделью Whisper и последующий построчный перевод на английский язык моделью MarianMT. Это обеспечивает унификацию входных данных для последующей генерации тестовых заданий.

\textbf{Компонент построения курса} предоставляет преподавателю визуальный интерфейс для создания иерархии тем (\texttt{CourseCreateView}, \texttt{TopicCreateView}). Связи между темами (предварительные требования и связанные темы) хранятся в базе данных как отношения «многие ко многим» и могут быть интерактивно отредактированы через API-эндпоинты \texttt{update\_topic\_relations\_api} и \texttt{reorder\_topics\_api}, что позволяет формировать направленный граф знаний без написания кода.

\textbf{Компонент распределения тем по портрету обучающегося} реализован в представлении \texttt{TopicDetailView}. При отображении темы система анализирует психологический профиль студента (в частности, факторы мотивации и нейротизма) и динамически ранжирует доступные типы контента (текст, видео, аудио), предлагая формат, наиболее соответствующий текущему когнитивному состоянию пользователя.

\subsection{Модуль выявления знаний обучающегося}
\label{sec:knowledge_identification}

Модуль выявления знаний обеспечивает адаптивное тестирование и формирование обратной связи на основе анализа уровня усвоения учебного материала. Он состоит из трёх взаимосвязанных компонентов.

\textbf{Компонент обработки материалов} принимает унифицированные текстовые данные из модуля предоставления знаний и передаёт их в генератор вопросов. Использование семантических эмбеддингов (Sentence-BERT) и алгоритма DBSCAN позволяет автоматически устранять смысловые дубликаты, формируя разнообразный банк заданий.

\textbf{Компонент построения тестирования} (\texttt{GenerateQuestionsView}, \texttt{TestCreateView}) создаёт структуру теста. Каждому сгенерированному вопросу (\texttt{TestItem}) автоматически присваиваются начальные параметры модели Раша: дискриминативность $a=1.0$, вероятность угадывания $c=0.0$ и параметр сложности $b$, зависящий от типа задания (easy: $-1.0$, medium: $0.0$, hard: $1.0$).

\textbf{Компонент оценки результатов} реализован в представлении \texttt{AdaptiveTestView}. В процессе прохождения теста система динамически подбирает следующее задание, минимизируя разницу $|b - \theta|$, где $\theta$ --- текущая оценка способности студента. После каждого ответа значение $\theta$ пересчитывается методом максимального правдоподобия (градиентный подъём), а результаты фиксируются в модели \texttt{UserTestResult} и влияют на прогресс по теме (\texttt{TopicProgress}).

\subsection{Модуль формирования рекомендаций}
\label{sec:recommendation_module}

Модуль создания рекомендаций синтезирует данные из всех предыдущих модулей для формирования индивидуальной образовательной траектории. Он включает четыре компонента, взаимодействующих через сигнальный механизм Django и прямые вызовы функций.

\textbf{Компонент обработки обучающих курсов} фильтрует опубликованные курсы по тегам, уровню сложности и доступности для конкретной учебной группы. \textbf{Компонент обработки портрета обучающегося} извлекает актуальные значения факторов A1--A4 из модели \texttt{PsychProfile} и применяет к ним интерпретации для маппинга на теги курсов. \textbf{Компонент обработки контекстуальных данных} запрашивает интегральный параметр активности $P$, рассчитанный модулем контекстной адаптации.

\textbf{Компонент построения рекомендаций} (\texttt{recommend\_courses\_for\_student}) объединяет полученные данные. Алгоритм ранжирует курсы, применяя весовые коэффициенты: бонусы за совпадение тегов с психологическим профилем, штраф за несоответствие сложности и множитель $P$, снижающий приоритет когнитивно тяжёлых курсов при неблагоприятных внешних условиях (например, при грозе или экстремальной температуре).
